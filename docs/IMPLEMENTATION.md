# 우선순위별 구현 결과

## P0 — 데이터 보존·안전성
- 제목·본문·AI 결과는 textContent/value로 표시합니다. inline 이벤트와 외부 CDN을 제거하고 CSP를 적용했습니다.
- 이전 ai_api_key를 앱 시작 시 제거합니다. 키를 읽거나 서버로 옮기지 않습니다.
- 기존 SermonDB를 버전 지정 없이 열어 Dexie v1(native v10)의 id·날짜·상태·documents를 유지합니다. 새 필드에 DB 버전 이행은 필요 없습니다.
- 전체 JSON 백업에 휴지통과 연결 자료도 포함합니다. 복원은 미리보기 후 새 ID로 추가하며 documents.sermonId를 다시 연결합니다. 두 저장소를 하나의 트랜잭션으로 처리해 실패하면 모두 되돌립니다.
- 복원은 덮어쓰지 않습니다. 같은 파일을 반복 복원하면 중복된다는 안내를 표시합니다.

## P1 — 개인 설교서재
- 본문·성경 본문·청중·태그·상태 편집, 저장 중/완료/실패 표시, 미저장 변경 이동 확인.
- 통합 검색, 성경·상태·청중·태그 필터, 최근 수정순/제목순 정렬.
- 실제 통계·최근 작업, 휴지통 복구, 모바일 메뉴·레이아웃.
- 외부 실행 의존성 0개. Node 서버도 표준 라이브러리만 사용합니다.

## P2 — 서버와 AI 초안
- 서버 비밀정보, 비밀번호 로그인, 8시간 HttpOnly/SameSite 세션, HTTPS에서 Secure cookie.
- 동일 출처 POST 확인, 입력 제한, 요청당 최대 6,000 출력 토큰, 분당 5회·하루 기본 30회·동시 1회.
- 시도한 요청을 디스크에 먼저 기록하므로 오류·재시작으로 일일 한도가 초기화되지 않습니다. 날짜는 UTC 기준입니다. 지속 디스크를 단일 인스턴스에 연결해야 합니다.
- 구조화 출력, 미완성/거절/잘못된 형식 거부, 60초 제한. 원문·키를 사용량 로그에 저장하지 않습니다.
- 결과는 AI 초안으로 별도 저장하며 원본 설교를 덮어쓰지 않습니다.
- GitHub Pages에서는 서버 연결 전 생성이 비활성화되고 요청문 다운로드가 가능합니다.
- 실제 키가 없어 유료 모델 호출·신학적 품질 평가는 실행하지 않았습니다. 모델과 단가는 평가 후 확정합니다.

## P3 — 조건부 도입
출처 검색 AI는 일반 검색의 실패가 측정된 다음 적용합니다. Drive 자료 자동 업로드·벡터 저장소 생성은 수행하지 않습니다. 승인 자료와 출처 위치를 확보한 후 30개 질문으로 정확도·시간을 비교합니다.

## 배포·되돌리기
- GitHub Pages의 동일 사이트 주소에서 업데이트하면 기존 DB를 읽습니다. 서버나 미리보기 주소로 바꾸면 저장 공간도 달라집니다. 원래 주소에서 백업 후 새 주소에서 복원하세요.
- DB 버전을 변경하지 않아 코드 복귀 후 구버전은 기존 제목 목록을 읽을 수 있지만 새 본문 UI를 제공하지 못하며 기존 보안 문제도 돌아옵니다. 데이터 복원은 별도 백업으로 진행합니다.
- 브라우저 삭제·기기 변경은 자동 동기화되지 않습니다.
