# 첨부 자료 기반 기능 설계와 구현

## 근거와 대응
| 제공 자료 | 확인한 요구 | 구현 |
|---|---|---|
| 프로젝트 01 성경본문 심층연구 PDF, 2~4쪽 | WORBS/BICS 분리, 본문별 Profile, A01~A05 선택, 실제 자료 접근 구분 | 연구 방식 선택, Book Profile 입력·자료 유형, 필요한 분야의 수동 근거 기록, 출처 상태 |
| 같은 PDF, 5~7쪽 | 6개 관점 QA, QA와 대표본 승인 분리, 미연결 자산을 실행했다고 표시하지 않기 | 6개 검수 기록, 별도 승인 게이트, 자료 부족 목록·자동 실행 아님 안내 |
| 성경연구 전문연구실 초보자 가이드 PDF, 2~4쪽 | 본문 관찰→문학→원어→배경→해석비교→신학→종합→검토, 출처·불확실성 보존 | 12개 연구 기록 항목, 주장별 분류·확실성·출처 연결, MD/JSON 인계 |
| 갈라디아서 1:1–5 LRC HTML | 자료 매핑과 위치, 책·정경 문맥, 이슈별 학자 비교, 원어·배경·적용, 한국어 TTS | 개인 HTML 가져오기와 LRC 섹션 자동 분류, 재인용 출처 기본값, 자료 읽어주기 |

제공 자료의 '승인·활성' 문구는 원래 프로젝트의 자기 보고이며 이 앱의 실제 연결을 증명하지 않습니다. 원문 사전, 66권 Profile, Runtime, Atlantis·히스기야터널은 실제 자산을 제공·연결하지 않았으므로 실행 가능한 것으로 표시하지 않습니다. 독립 QA 엔진을 실행한 것으로도 표시하지 않습니다.

## 데이터 보존과 개인정보
- 기존 SermonDB와 두 저장소를 그대로 사용합니다. 새 DB 버전이나 파괴적 이행은 없습니다.
- 연구는 각 설교의 research 필드, 개인 자료는 기존 documents 저장소에 보관합니다.
- 복원은 기존 설교·자료를 유지하며 새 식별자로 추가하고 첨부 연결을 다시 매핑합니다.
- 연구 저장 시 revision을 확인해 다른 탭의 연구를 덮어쓰지 않습니다. 원고 편집도 최신 연구를 유지합니다.
- 개인 원문 파일은 공개 저장소에 넣지 않습니다. 서버는 추가된 코드 모듈만 제공합니다.
- HTML 스크립트·스타일·리소스·이벤트는 화면에 붙이지 않으며 텍스트만 표시합니다.

## 실제 자료를 서재에 넣는 순서
1. 새 설교를 저장하거나 기존 설교를 엽니다.
2. 본문 연구실 → 출처 · 자료 → 개인 연구 자료 가져오기에서 첨부받은 PDF 2개와 HTML을 선택합니다.
3. HTML 자료를 펼쳐 **LRC 항목을 빈 연구칸에 채우기**를 누릅니다. 주석 13종은 원문 미확인 재인용 자료로 등록됩니다.
4. 빠진 본문 관찰·신학 종합·한계와 출처 확인 내용을 보완하고 연구 저장을 누릅니다.
5. 보완 · 인계에서 필요한 자료와 후속 작업을 확인합니다. JSON/MD 인계와 전체 백업은 별개 용도입니다.

첨부 파일이 사용자의 브라우저 DB에 자동 입력되었다고 주장하지 않습니다. 파일 선택 없이 원격에서 브라우저의 개인 저장소에 접근할 수 없습니다.

검증: 서버·데이터·연구 규칙 자동 테스트 18개 통과. Chromium에서 실제 제공 HTML의 9개 LRC 섹션과 주석 13종 추출, PDF 2개 보관, 기존 원고 보존, 원문 미확인 상태 유지, 검수 무효화, 승인 차단, 작업·인계·다시 열기, 375px 레이아웃을 확인했습니다. 기존 편집·AI 모의 생성 브라우저 검증도 통과했습니다. 실제 유료 AI나 전문 연구 엔진은 호출하지 않았습니다.

연구에서 설교로 넘어갈 때는 보완 · 인계의 **설교 작성 요청문 다운로드**를 사용합니다. 종합 해석 작성이 선행 조건이며 출처·검수·미해결 사항을 함께 전달합니다.
